# 1. PRÉSENTATION GÉNÉRALE

## 1.1 Objectif

Le projet consiste à développer deux modules transversaux dans Coccinelle :

1. **BIA Enterprise** : centre de supervision technique, de sécurité, d'intégrité et de continuité du système.
2. **Audit interne** : centre de contrôle des opérations, de vérification des preuves, de gestion des constats et de suivi des recommandations.

Ces deux modules doivent partager une identité visuelle et une infrastructure de journalisation, mais conserver des responsabilités et des autorisations distinctes.

## 1.2 Architecture organisationnelle

Les deux modules sont rattachés au niveau organisationnel de CAFE YAYO.

Ils ne constituent :
- ni des départements commerciaux ;
- ni des succursales ;
- ni des caisses opérationnelles ;
- ni des services de vente.

Ils supervisent et contrôlent les différentes activités de l'organisation.

## 1.3 Technologies du projet

| Composant | Technologie |
|---|---|
| Frontend | Next.js 16.3 App Router |
| Backend | Next.js Server Actions / DAL |
| ORM | Prisma 7 |
| Base de données | PostgreSQL |
| Authentification | Better Auth |
| Graphiques | Recharts |
| Journalisation | Pino |
| Tests E2E | Playwright |
| Surveillance | Worker Node.js indépendant |
| Sauvegarde | pgBackRest ou PostgreSQL Base Backup + WAL |

Les versions exactes des dépendances devront être vérifiées dans le projet existant avant implémentation.

## 2.4 Database Monitoring

Fonctionnalités :

- Vérifier la disponibilité PostgreSQL.
- Surveiller les connexions.
- Identifier les requêtes lentes.
- Surveiller les transactions longues.
- Détecter les verrous.
- Suivre la taille des tables.
- Suivre l'évolution du stockage.
- Mesurer les performances des requêtes.

Sources techniques possibles :

- `pg_stat_activity`
- `pg_stat_database`
- `pg_stat_statements`
- `pg_locks`
- `pg_database_size`

Les collecteurs doivent utiliser des droits minimaux, de préférence en lecture seule.

## 2.5 Security Center

Fonctionnalités :

- Suivi des connexions réussies.
- Suivi des connexions échouées.
- Détection des accès refusés.
- Surveillance des changements de rôles.
- Surveillance des permissions sensibles.
- Historique des sessions.
- Détection des comportements inhabituels.
- Gestion des incidents de sécurité.

Le système ne doit pas enregistrer les mots de passe, jetons d'accès ou secrets dans les journaux.

## 2.6 Integrity Control

Ce sous-module contrôle la cohérence des données métier.

### Contrôles des ventes

- Tickets sans lignes.
- Lignes de vente incohérentes.
- Ventes annulées sans justification.
- Totaux de tickets incohérents.
- Paiements sans transaction correspondante.

### Contrôles des stocks

- Stock négatif non autorisé.
- Mouvement sans référence.
- Sortie sans justification.
- Écart entre mouvements et stock théorique.
- Ajustement anormal.

### Contrôles des caisses

- Solde incohérent.
- Mouvement sans référence.
- Opération sans validation obligatoire.
- Écart de clôture.
- Transfert déséquilibré.

### Contrôles des achats

- Réception sans commande liée lorsque celle-ci est obligatoire.
- Facture en doublon.
- Montant incohérent.
- Paiement sans justificatif.

**Règle essentielle :** le moteur d'intégrité détecte et signale les anomalies. Il ne corrige jamais automatiquement les données métier.

## 2.7 Backup & Recovery

Fonctionnalités :

- Sauvegarde complète.
- Archivage continu des WAL.
- Historique des sauvegardes.
- Vérification des fichiers.
- Contrôle de l'intégrité.
- Tests de restauration.
- Historique des restaurations.
- Gestion du plan de reprise.

Objectifs initiaux à valider avec l'infrastructure :

| Paramètre | Proposition |
|---|---|
| RPO | 15 minutes |
| RTO | 2 heures |
| Sauvegarde complète | Quotidienne |
| Archivage WAL | Continu |
| Test de restauration | Mensuel |
| Exercice de reprise | Trimestriel |

Ces valeurs sont des objectifs de conception, pas des garanties. Elles devront être validées par des tests réels et en fonction des moyens disponibles.

## 2.8 Alerting & Incidents

Niveaux de criticité :

- Information
- Faible
- Moyenne
- Élevée
- Critique

Cycle d'un incident :

1. Détection.
2. Création.
3. Classification.
4. Attribution.
5. Diagnostic.
6. Intervention.
7. Vérification.
8. Résolution.
9. Clôture.
10. Historique.

**Les opérations de CAFE YAYO sont-elles correctement exécutées, justifiées, autorisées et contrôlées ?**

# 5. RÔLES ET PERMISSIONS

## 5.1 Matrice générale

| Rôle | BIA | Audit interne |
|---|---|---|
| Direction / PCA | Consultation synthétique | Consultation synthétique |
| Administrateur IT | Gestion technique autorisée | Pas d'administration de l'audit |
| Responsable infrastructure | Supervision et incidents | Lecture des éléments autorisés |
| Auditeur interne | Consultation limitée des preuves techniques | Gestion des missions et constats |
| Responsable audit | Consultation | Gestion et supervision de l'audit |
| Direction financière | Alertes autorisées | Consultation des rapports autorisés |

## 5.2 Règles fondamentales

- L'accès doit respecter le principe du moindre privilège.
- Les permissions doivent être vérifiées côté serveur.
- Les auditeurs ont un accès en lecture seule aux données métier sources.
- Les auditeurs peuvent créer et gérer leurs constats et recommandations.
- Les auditeurs ne peuvent pas modifier les ventes, les stocks ou les mouvements de caisse.
- Les administrateurs IT ne doivent pas disposer automatiquement de droits d'approbation financière.
- Les accès sensibles doivent être journalisés.

# 14. RÉSULTAT FINAL ATTENDU

À la fin du projet, Coccinelle doit disposer de deux modules Enterprise complémentaires.

## BIA Enterprise

Un centre de contrôle capable de :
- surveiller la santé du système ;
- contrôler la base de données ;
- suivre la sécurité ;
- détecter les incohérences ;
- surveiller les sauvegardes ;
- gérer les incidents ;
- produire des rapports techniques.

## Audit interne

Un centre de contrôle capable de :
- planifier les audits ;
- examiner les opérations ;
- consulter les preuves ;
- détecter les anomalies ;
- formaliser les constats ;
- suivre les recommandations ;
- produire des rapports professionnels.

**BIA Enterprise surveille la fiabilité technique de Coccinelle.**

**Audit interne contrôle la fiabilité des opérations de CAFE YAYO.**

Les deux modules doivent fonctionner ensemble sans confusion de responsabilités ni de permissions.
